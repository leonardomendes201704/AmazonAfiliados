# US-01 · Monorepo e scripts de processo

**Como** desenvolvedor, **quero** um monorepo pnpm com qualidade e scripts de processo prontos **para** que toda tarefa seguinte tenha base, lint, testes e rastreabilidade.

> Até a T-01.3 existir, o status é atualizado à mão (aqui e em `docs/backlog/BACKLOG.md`).

## Contexto mínimo (ler só isto)

- `docs/processo/scrum.md` §3, §7 e §8
- `docs/arquitetura/adr/ADR-001-monorepo-typescript.md`
- `docs/arquitetura/adr/ADR-008-backlog-markdown-scripts.md`
- `docs/backlog/historias/_MODELO.md` (formato lido por `scripts/backlog.ts`)

## Critérios de aceite

- [ ] **CA1:** dado um clone limpo, quando rodo `pnpm i && pnpm lint && pnpm typecheck && pnpm test`, então tudo passa com código de saída 0.
- [ ] **CA2:** dado o monorepo, quando listo `apps/` e `packages/`, então existem `api`, `worker`, `web`, `db` e `shared`, cada um com `package.json` e `tsconfig.json` (strict, ESM, Node 22).
- [ ] **CA3:** dado um commit com erro de formatação, quando faço `git commit`, então o hook `pre-commit` (biome --staged) bloqueia; `pre-push` roda o typecheck.
- [ ] **CA4:** dado `docs/backlog/`, quando rodo `pnpm backlog status` e `pnpm backlog iniciar T-01.3`, então o status muda na história e na linha do `BACKLOG.md`; `concluir` grava o sha; formato inválido falha com mensagem.
- [ ] **CA5:** dado o repositório, quando rodo `pnpm rastreabilidade`, então `docs/rastreabilidade.md` é gerado a partir do frontmatter, das evidências e do `git log --grep "(T-"`.
